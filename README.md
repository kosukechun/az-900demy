# AZ-900 問題集

Q1〜Q6のスクリーンショットから転記した各70問、計420問を使うシンプルな問題アプリです。問題文・選択肢は `data/Q1.txt` 〜 `data/Q6.txt` に保存しています。

- 単一選択はタップするとすぐに正誤と解説を表示します。
- 複数選択は選び終えてから「回答する」で判定します。
- 回答済みの問題と前回の場所を、端末の同じブラウザーに保存します。
- ダークモードで、問題文も暗い背景と明るい文字で表示します。
- 各セットの「最初から解く」で、そのセットだけ回答をリセットして問題1から解き直せます。「続きから解く」では保存した回答を残します。
- iPadの縦・横画面に対応します。文章は画面幅に合わせて折り返し、文字サイズの変更にも追従します。

問題画像は読み込みません。元の問題文をテキストに転記し、OCRで誤読された製品名・IP・ID・数字・記号などを校正しています。空欄は `__________`、多層防御の図は文字の並びで表現します。元画像に写っていない選択肢は補っていません。

元のPNG、表示用WebP、OCRの一時画像は削除済みです。問題の編集・ビルド・利用に画像やOCR環境は不要です。過去にコミット済みの画像はGitの過去履歴には残りますが、アプリの動作・公開には使用しません。

正解・解説は学習用に作成したものです。スクリーンショットには教材の公式解答が含まれていないため、教材の正答と一致することを保証するものではありません。旧名称と現在の仕様が重なる問題などは解説内で区別しています。

## 開く

PCでは `index.html` を直接開けます。ローカルサーバーを使う場合はNode.jsがあれば、依存パッケージのインストールなしで起動できます。

```powershell
cd C:\Users\kosuk\script\az-900-app_udemy
npm start
```

表示された `http://127.0.0.1:4173` をPCのブラウザーで開きます。停止はターミナルで `Ctrl + C`。変更が表示されない場合は再読み込みしてください。

## iPadでの表示

縦・横画面に合わせて配置を切り替えます。問題文は18px、選択肢は17pxを基本に、画面幅に合わせて自然に折り返します。小さい画面でも文字サイズを保ち、画像全体の縮小で読みにくくなることを避けています。選択肢のタップ領域は最低56px、主なボタンは48px以上です。問題の移動メニューは16pxの文字にし、選択時の不要な拡大を抑える構成です。

iPadでは公開後のPages URLをSafariで開いてください。PCの `127.0.0.1` はiPadからPCへ接続するURLではありません。実機iPad・実ブラウザーの確認は未実施のため、Safari固有の描画や操作まで検証済みとはしていません。

## GitHub PagesでiPadから使う

### 無料で使う条件

**GitHub FreeのPublic（公開）リポジトリと、標準の `github.io` URLを使えば、GitHub Pagesのホスティングは無料です。** このアプリには有料APIやデータベースはありません。独自ドメインを購入する必要もありません。[GitHub Pagesの提供条件](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

Publicリポジトリでは、ソースと問題文も他の人から閲覧できます。PrivateリポジトリからのPages公開には、対応する有料プランなどが必要です。PrivateでもPagesのサイト自体が非公開になるとは限りません。

このワークフローの `ubuntu-latest` は標準ランナーで、Publicリポジトリでの実行は無料です。公開用アーティファクトの保持期間は1日にしています。Privateリポジトリや大型ランナーなどの別条件では課金ルールが変わります。[Actionsの料金条件](https://docs.github.com/en/billing/concepts/product-billing/github-actions)

Pagesにはサイト1GB、月間転送量100GBのソフト上限などがあります。制限を超えた場合は提供制限などの対象になり得るため、無制限のサービスではありません。[Pagesの制限](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)

### 1. GitHubへアップロードする

公開用のワークフローを `.github/workflows/pages.yml` に用意しています。実際のpushや公開はまだ行っていません。このリポジトリを無料で公開する場合は、GitHub上でPublicであることを確認します。

このフォルダのターミナルで、次を実行します。すでにコミット済みなら `git push origin main` だけで構いません。

```powershell
cd C:\Users\kosuk\script\az-900-app_udemy
git add -A
git commit -m "Add AZ-900 practice app"
git push origin main
```

### 2. Pagesの公開元を設定する

1. [リポジトリのPages設定](https://github.com/dk-inouekosu/az-900-app_udemy/settings/pages)を開きます。
2. **Build and deployment → Source → GitHub Actions** を選びます。
3. リポジトリの **Actions → Deploy quiz to GitHub Pages → Run workflow** を開きます。
4. Branchを **main** にして、**Run workflow** を押します。
5. ワークフローが緑色の成功表示になったら、デプロイ結果のURLを開きます。

`Source` にGitHub Actionsが出ない場合は、リポジトリの権限・プラン・公開設定を確認します。初回の実行がPages未設定で失敗していた場合は、設定後に再実行してください。

このリポジトリの通常のURLは `https://dk-inouekosu.github.io/az-900-app_udemy/` です。これは公開完了を確認したURLではありません。実際のURLはデプロイ結果を確認してください。

### 3. iPadで開く・後から更新する

iPadのSafariでPagesのURLを開きます。ホーム画面へ追加する場合は、Safariの共有メニューから「ホーム画面に追加」を選びます。進捗はブラウザーごとの保存で、PCとiPadの間では同期しません。

公開後はアプリの変更を `main` にpushすると自動更新されます。READMEなど公開対象以外の変更だけでは実行されない場合があるため、その場合はActionsから手動実行できます。画面が古い場合は再読み込みします。

公開方法は[GitHub公式のカスタムワークフローの説明](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)に沿っています。

| Q1-14、Q4-08 | 旧名称と現在の名称の選択肢が重複 |
| Q1-22、Q4-01 | 要件を満たすサービスが複数 |
| Q2-17、Q6-60 | そのままでは適切な選択肢がない |
| Q2-55 | グループへの通知方法によって判断が変わる |
| Q3-06 | 下の選択肢が画像に写っていない |
| Q3-13、Q4-68、Q5-36 | 正しい候補が指定された選択数に収まらない |
| Q3-30 | 旧EAポータルを前提にした条件 |
| Q3-52、Q6-44 | Azure Backupのサービス分類の粒度が不明 |
| Q3-68 | ストレージ技術とディスク種類が混在 |

## 検証・更新

```powershell
npm run check
npm run test
npm run build
```

`dist/` に公開に必要なファイルだけをまとめます。APIキー、ログイン、データベース、外部CDNへの依存はありません。

問題文と選択肢は `data/Q1.txt` 〜 `data/Q6.txt` で管理します。各問題の形式は次のとおりです。見出しのID、選択肢の区切り、Aから順番のラベルは維持します。問題文では空行や改行を使用できます。

```text
=== Q1-01 ===
問題文をここに記載します。
--- 選択肢 ---
A. 1つ目の選択肢
B. 2つ目の選択肢
```

正解と解説は `data/answers-Q1.tsv` 〜 `data/answers-Q6.tsv` で管理します。列は `問題番号|正解番号|解説|参考資料キー（省略可）`。正解番号は1から、複数選択は `1,2`、同等の正解の組は `1,5;2,5`、解説のみは `?` です。

TXTまたは解説を更新したら、次を実行して `data/questions.js` を再生成し、そのファイルもコミットします。生成にはPython 3の標準ライブラリだけを使います。

```powershell
python scripts/build_data.py
```

起動時は生成済みの `data/questions.js` を読み込むため、PythonもTXTのオンライン取得も不要です。`index.html` を直接開く使い方も継続できます。問題IDと保存形式は以前の版と同じなので、同じブラウザー・同じURLなら回答履歴を引き継げます。

本環境では420問と1,252個の選択肢、TXTと実行用データの一致、画像依存がないこと、403問の正解操作、単一・複数選択、再回答、セットごとのリセット、続きからの開始、保存・再読み込みを検証しています。ブラウザー操作用の接続が利用できないため、実ブラウザーと実機iPadの画面検証は未実施です。
